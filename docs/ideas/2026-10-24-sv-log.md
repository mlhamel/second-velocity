# sv-log: live shard feed (spectator CLI)

`sv-log` is a headless command-line client that connects to a running shard
and streams its live events — market news, port price changes, dockings,
deaths, explosions — like `tail -f` for the galaxy. Approved 2026-10-24.

## Locked scope answers (owner, 2026-10-24)

- **Build**: MVP only — one session, pure client-side, zero server/protocol
  changes, no ADR. Phase C below is deferred to its own session.
- **Output**: human-readable by default, `--json` included in the MVP
  (one JSON object per line; the bridge for a future playtest Discord bot,
  come-back roadmap phase 5).
- **Spectator rule**: never sends `LoginRequest`, so no ship spawns and
  nothing is persisted for it. This is only clean on `--storage`-backed
  shards (the same rule ghost pilots accepted): storage-less shards
  auto-spawn a default ship for every authorized connection
  (`authorize_clients`), which is out of scope to fix.
- **No bench scenario, by design**: AGENTS.md's "every gameplay feature
  ships with a benchmark scenario" rule covers sim mechanics; sv-log is an
  external client/ops tool with no server-side sim change, so an in-process
  integration test covers the loop instead (ghost-pilots precedent).

## Why this architecture

Everything the MVP shows is already on the wire, broadcast to all clients:
`Notice` events carry every ≥15% price move as text
(ADR-0015 living markets), `PortMarket` components carry every port's full
price list and replicate continuously, `PlayerDied`/`Explosion`/`DockedAt`
carry the galaxy feed. A spectator client needs no new protocol and cannot
desync from the shard: it is pure read-only observation.

The tool is a headless Bevy app (MinimalPlugins + replicon + renet2 UDP,
the MCP harness client pattern) with diff-based `PortMarket` tracking
(keeps its own price board and emits change lines), wall-clock timestamps,
bounded queues, and auto-reconnect on the netcode 15s idle drop
(`ensure_connected` pattern). Status lines go to stderr so stdout stays a
clean pipeable feed.

## Out of MVP (explicitly — Phase C, needs ADR-0017)

- `MarketClock` replicated component (sim day / economy tick number)
- `RequestCandles`/`CandlesResponse` events exposing server-side OHLCV
  candles and supply counters, including SQLite history
- Spectator flag via netcode `user_data` for storage-less shards
- Any protocol addition changes the protocol hash: shard and tools must
  ship together (fine pre-M3)

## Risks (accepted)

- Storage-less shards spawn a ghost ship for the connection — documented;
  sv-log targets `--storage` shards only
- `Notice` text is pre-formatted prose (no structured payload); `--json`
  wraps the text, and Phase C is the structured-data answer
- No interest management: the spectator receives the full-galaxy firehose
  (the same data every client gets); fine at friends-playtest scale
