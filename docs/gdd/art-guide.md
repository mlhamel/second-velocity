# Art Guide

[active] — the entry point for contributing art

The current art is placeholder-grade: every texture under `assets/textures/`
was generated by `ops/generate_placeholder_art.py`. Replace the files, keep
the names and sizes, and the game picks them up automatically.

## How art reaches the game

1. Content files in `content/` reference art by relative path:
   `sprite: Some("textures/ships/shuttle.png")` in a ship or planet
   definition, or `icon: Some("textures/outfits/light-blaster.png")` on an
   outfit / port commodity entry (paths are relative to `assets/`).
2. Pack validation (`cargo test -p evr-data`) fails if a referenced file is
   missing — no dangling art references, ever.
3. The client loads the PNG at spawn. If a definition has no `sprite` field,
   the game falls back to a procedural shape, so content works before art
   exists.

## Conventions

| Kind | Path | Size | Notes |
|---|---|---|---|
| Ship | `assets/textures/ships/<ship-id>.png` | 128×128 | **Faces +x (east).** Full-color pre-rendered top-down sprite on transparent background (`shuttle.png`, `turncoat.png`, `patrol.png`) |
| Planet | `assets/textures/planets/<planet-id>.png` | 128×128 | Natural colors; no tint applied |
| Station | `assets/textures/stations/docking-ring.png` | 128×128 | Transparent top-down docking ring; station content can select its own sprite |
| Chief | `assets/textures/chiefs/<planet-id>.png` | 128×128 | Bust portrait on dark/transparent background; displayed in the docking encounter panel |
| Station master | `assets/textures/chiefs/<station-id>.png` | 128×128 | Uses the same encounter panel and procedural fallback as chiefs |
| Commodity | `assets/textures/commodities/<commodity-id>.png` | 128×128 | Cargo-container icon shown as a small square beside each Market row (~20 px) |
| Outfit | `assets/textures/outfits/<outfit-id>.png` | 128×128 | Kind silhouette (weapon / shield bubble / fuel canister) shown beside each Outfitter row (~20 px) |

- RGBA PNG, transparent background
- Ship sprites render at ~44 px world size in natural colors (fallback untextured hulls use faction-tinted 24×12 rectangles); planets at `radius * 2`
- File name should match the content id — makes replacement obvious

## Skies

Every star system gets a procedurally generated night sky (`crates/client/src/sky_gen.rs`)
— no image assets needed. The seed is derived from the system id, so:

- every player generates a pixel-identical sky for the same system
- every system looks distinct automatically (band position, width, density,
  cloud stretch, palette warmth, star field, clusters, one distant galaxy)
- the same world position always maps to the same sky region

The sky renders as a fullscreen background behind all world entities (z=-30)
and follows the camera. Generated at 64x64 and stretched to the viewport —
larger textures don't render reliably on all GPUs.

Art direction lives in the generator constants: star color-temperature
spread, band palette warmth, cluster count, spike frequency. Designers
tweak numbers, not pixels.

## Regenerating placeholders

```bash
python3 ops/generate_placeholder_art.py
```
